# 教学微课 AI 开发平台：功能需求规格说明书

> 文档版本：V1.0  
> 编制日期：2026-08-02  
> 文档类型：PRD + SRS  
> 优先级说明：P0 为 MVP 必须完成，P1 为首个正式版本，P2 为后续增强

---

## 1. 文档目的

本文档定义教学微课 AI 开发平台的用户角色、业务流程、功能模块、数据对象、页面交互、权限、验收标准和非功能需求，作为产品设计、前后端开发、Agent 开发、测试和项目验收的共同依据。

---

## 2. 产品范围

平台接收教师提供的课程需求和参考材料，通过多 Agent 工作流完成课程蓝图设计、教学资源生成、质量审核、人工修改、版本管理和课程包导出。

### 2.1 核心输入

- 课程名称和主题；
- 学科、专业或领域；
- 学段、年级或授课对象；
- 课程时长；
- 教学场景；
- 课程任务；
- 教学目标或预期成果；
- 重点、难点和易错点；
- 教学方法偏好；
- 课程风格和语言；
- 教材、课程标准、教学大纲、旧教案、PPT 等文件；
- 学校模板和特殊要求。

### 2.2 核心输出

- 课程蓝图；
- 教学设计；
- PPTX 课件；
- 学习任务单；
- 课后练习与答案解析；
- 微课视频脚本；
- 教师逐字稿；
- 质量报告；
- 引用与来源清单；
- ZIP 课程资源包。

---

## 3. 用户角色

| 角色 | 说明 | 核心权限 |
|---|---|---|
| 教师 | 主要使用者 | 创建、生成、编辑、审核、导出自己的课程 |
| 课程负责人/教研员 | 审核与模板管理 | 查看团队课程、评论、审批、管理共享模板 |
| 管理员 | 系统管理 | 用户、模型、提示模板、系统配置、审计 |
| 游客/试用用户 | 可选 | 使用示例或受限生成，不保存敏感数据 |

MVP 可以只实现“教师”和“管理员”两个角色，但数据模型应预留团队和审批能力。

## 4. 核心业务流程

### 4.1 新建课程流程

1. 教师创建课程项目；
2. 填写基础信息；
3. 输入自然语言要求；
4. 上传参考材料；
5. 系统解析输入并识别缺失项；
6. 教师确认系统补全的信息；
7. 生成课程蓝图；
8. 教师审核并锁定蓝图；
9. 系统并行生成六类核心资源；
10. 系统执行规则检查和 AI 质量审核；
11. 不合格项自动定向返工；
12. 教师查看、编辑和局部重生成；
13. 教师确认课程版本；
14. 导出单个文件或完整 ZIP 包。

### 4.2 局部修改流程

1. 教师选择具体资源、章节、页面或题目；
2. 输入修改指令；
3. 系统判断影响范围；
4. 仅调用对应 Agent；
5. 生成新版本；
6. 显示新旧差异；
7. 教师接受、继续修改或恢复旧版本。

### 4.3 蓝图变更流程

课程蓝图属于上游权威数据。教师修改目标、对象、时长或知识点时，系统必须提示受影响资源，并提供：

- 仅保存蓝图；
- 更新受影响资源；
- 重新生成全部资源；
- 复制为新版本。

# 6. 功能需求

## 6.1 用户与权限

### FR-USER-001 注册与登录（P0）

支持用户名/邮箱和密码登录。MVP 可由管理员创建用户。

**验收标准：**

- 密码不可明文保存；
- 登录成功返回访问令牌；
- 未登录用户不能访问课程数据；
- 用户只能查看和修改自己拥有的课程；
- 连续失败可进行简单限流。

### FR-USER-002 用户偏好（P1）

保存默认学段、常用课程时长、语言、模型和导出模板。

### FR-USER-003 团队与审批（P2）

支持课程共享、评论、审核和发布状态。

---

## 6.2 课程项目管理

### FR-COURSE-001 创建课程项目（P0）

字段包括：

| 字段 | 必填 | 示例 |
|---|---:|---|
| 课程名称 | 是 | 牛顿第二定律 |
| 学科/专业 | 是 | 高中物理 |
| 学段/年级 | 是 | 高一 |
| 授课对象 | 是 | 已学习运动学基础的学生 |
| 课程时长 | 是 | 15 分钟 |
| 教学场景 | 是 | 课前预习/课堂讲解/复习/实训 |
| 课程任务 | 是 | 理解力、质量和加速度关系 |
| 语言 | 是 | 中文 |
| 教学模式 | 否 | 讲授+探究 |
| 风格要求 | 否 | 简洁、案例驱动 |
| 额外提示 | 否 | 使用生活化案例 |

### FR-COURSE-002 项目状态（P0）

支持：

- 草稿；
- 需求待确认；
- 蓝图生成中；
- 蓝图待确认；
- 资源生成中；
- 质量检查中；
- 待教师审核；
- 已完成；
- 生成失败；
- 已归档。

### FR-COURSE-003 复制、归档、删除（P1）

删除前必须二次确认；软删除优先。

### FR-COURSE-004 课程搜索与筛选（P1）

按名称、学科、状态、创建时间和更新时间筛选。

---

## 6.3 需求输入与智能补全

### FR-INPUT-001 表单输入（P0）

结构化表单提供必填校验、字数提示和示例。

### FR-INPUT-002 自然语言输入（P0）

教师可以直接描述需求，需求解析 Agent 将其转换为结构化字段。

### FR-INPUT-003 缺失项识别（P0）

系统应识别影响课程设计的关键信息是否缺失，例如：

- 授课对象不明确；
- 时长不明确；
- 目标过于宽泛；
- 主题范围过大；
- 是否使用上传材料不明确；
- 输出语言不明确。

系统应给出两种方式：

1. 教师补充；
2. 使用系统建议值并明确标注假设。

### FR-INPUT-004 需求冲突检测（P0）

例如：

- 5 分钟课程要求覆盖整章；
- 小学生课程要求推导高等数学公式；
- 要求“完全依据教材”但未上传教材；
- 要求生成 30 页 PPT 但课程仅 8 分钟。

系统应提示冲突并给出调整建议。

### FR-INPUT-005 需求确认快照（P0）

每次生成蓝图前保存一份输入快照，以便追踪生成依据。

---

## 6.4 文件与知识材料

### FR-FILE-001 文件上传（P0）

MVP 支持：

- PDF；
- DOCX；
- PPTX；
- TXT；
- Markdown。

建议单文件限制 30 MB，总材料限制可配置。

### FR-FILE-002 文件解析（P0）

提取：

- 标题和章节；
- 正文文本；
- 表格文本；
- PPT 页面文本；
- 文档元数据。

扫描 PDF 的 OCR 可作为 P1，MVP 对无法解析文件给出明确提示。

### FR-FILE-003 材料用途设置（P0）

教师可以标记：

- 必须遵循；
- 优先参考；
- 仅供风格参考；
- 禁止外部补充；
- 允许外部知识补充。

### FR-FILE-004 材料摘要和知识点确认（P1）

系统展示解析摘要、术语和知识点，教师可以修改后再用于生成。

### FR-FILE-005 引用追踪（P1）

生成内容保存来源片段 ID，质量报告显示哪些结论来自哪些材料。

### FR-FILE-006 文件删除与数据清理（P0）

教师可删除材料；删除后禁止后续 Agent 继续引用。

## 6.5 课程蓝图

课程蓝图是系统最重要的数据对象。

### FR-BLUEPRINT-001 蓝图生成（P0）

蓝图至少包括：

```yaml
course_identity:
  title:
  subject:
  audience:
  duration_minutes:
  scenario:
learning_analysis:
  prior_knowledge:
  learner_characteristics:
  likely_misconceptions:
objectives:
  - id:
    domain:
    behavior:
    condition:
    criterion:
knowledge_points:
  - id:
    name:
    level:
    prerequisite:
    source_refs:
key_points:
difficulty_points:
teaching_strategy:
timeline:
  - segment_id:
    name:
    start_minute:
    end_minute:
    purpose:
    teacher_action:
    learner_action:
    evidence_of_learning:
assessment_plan:
terminology:
resource_constraints:
```

### FR-BLUEPRINT-002 蓝图编辑（P0）

教师可以直接修改所有字段。

### FR-BLUEPRINT-003 蓝图审核（P0）

蓝图未确认前不生成全部资源。支持：

- 通过；
- 退回 AI 修改；
- 局部重生成；
- 手工编辑后通过。

### FR-BLUEPRINT-004 目标设计（P0）

目标必须尽量使用可观察行为，例如“解释、比较、判断、完成、设计”，避免仅使用“了解、熟悉”。

每个目标应关联：

- 知识点；
- 教学活动；
- 学习证据；
- 练习题。

### FR-BLUEPRINT-005 时间预算（P0）

各教学环节时间之和必须与总时长一致，允许误差不超过配置值。

### FR-BLUEPRINT-006 术语表（P0）

所有资源统一使用术语表，缩写首次出现时给出全称。

## 6.6 教学设计生成

### FR-PLAN-001 完整教学设计（P0）

至少包括：

1. 课程基本信息；
2. 教学内容分析；
3. 学情分析；
4. 教学目标；
5. 教学重点和难点；
6. 教学方法与资源；
7. 教学过程；
8. 教师活动；
9. 学生活动；
10. 设计意图；
11. 时间分配；
12. 课堂评价；
13. 板书或页面设计；
14. 课后任务；
15. 教学反思占位。

### FR-PLAN-002 表格与文本双视图（P1）

教师可在教学过程表格和结构化文本之间切换。

### FR-PLAN-003 局部重写（P0）

支持针对某一环节进行：

- 更具体；
- 更简洁；
- 增强互动；
- 更符合学情；
- 增加案例；
- 调整时间；
- 自定义指令。

### FR-PLAN-004 模板选择（P1）

支持基础教育、高校、职业教育三类模板。

## 6.7 PPT 课件

### FR-PPT-001 页面规划（P0）

先输出页面结构，再渲染 PPTX。每页应包含：

- 页面 ID；
- 页面标题；
- 页面目的；
- 核心信息；
- 视觉形式建议；
- 教师备注；
- 对应时间；
- 对应脚本段落。

### FR-PPT-002 PPTX 导出（P0）

支持使用内置模板生成可编辑 PPTX。

### FR-PPT-003 页面类型（P0）

至少支持：

- 封面；
- 学习目标；
- 情境导入；
- 概念讲解；
- 流程图；
- 对比；
- 案例；
- 课堂提问；
- 练习；
- 总结；
- 课后任务。

### FR-PPT-004 信息密度规则（P0）

规则可配置，例如：

- 单页只表达一个中心；
- 正文字数上限；
- 标题长度上限；
- 避免大段逐字稿进入 PPT；
- 关键概念突出；
- 图片占位和来源提示。

### FR-PPT-005 上传学校模板（P1）

教师可上传 PPTX 模板，系统读取母版和常用版式。

### FR-PPT-006 页面级重生成（P1）

重做单页，不改变其他页面编号。

### FR-PPT-007 图片能力（P2）

支持素材搜索、AI 图片、图标库和图表自动生成。MVP 可仅生成图片占位说明。

## 6.9 课后练习

### FR-EXERCISE-001 题型（P0）

支持：

- 单项选择；
- 多项选择；
- 判断；
- 填空；
- 简答；
- 案例分析；
- 实践任务。

### FR-EXERCISE-002 题目配置（P0）

教师设置：

- 题量；
- 题型；
- 难度比例；
- 是否包含答案；
- 是否包含解析；
- 是否限定知识点。

### FR-EXERCISE-003 题目元数据（P0）

每题保存：

- 题目 ID；
- 题型；
- 题干；
- 选项；
- 答案；
- 解析；
- 难度；
- 对应目标；
- 对应知识点；
- 预计用时；
- 来源或生成依据。

### FR-EXERCISE-004 自动校验（P0）

检查：

- 选择题答案是否存在；
- 选项是否重复；
- 单选题是否只有一个正确答案；
- 题干是否泄露答案；
- 答案和解析是否一致；
- 是否覆盖目标；
- 是否出现超纲内容。

### FR-EXERCISE-005 题目替换（P0）

支持单题重生成和锁定已确认题目。

## 6.11 教师逐字稿

### FR-VERBATIM-001 逐字稿生成（P0）

逐字稿必须：

- 与时间线一致；
- 与 PPT 页序一致；
- 包含过渡语；
- 包含提问、停顿和反馈建议；
- 使用适合授课对象的语言；
- 区分“必须讲”和“可选补充”。

### FR-VERBATIM-002 语速与字数（P0）

教师可选择慢、标准、快，系统根据时长预算控制字数。

### FR-VERBATIM-003 风格（P1）

支持：

- 正式；
- 亲切；
- 互动；
- 学术；
- 故事化；
- 实训指导。

### FR-VERBATIM-004 提词器视图（P1）

大字号、段落计时、当前 PPT 页提示。

## 6.12 多 Agent 运行中心

### FR-AGENT-001 运行进度（P0）

展示节点状态：

- 等待；
- 运行中；
- 已完成；
- 需要教师确认；
- 自动返工；
- 失败；
- 已跳过。

### FR-AGENT-002 流式输出（P1）

优先使用 SSE 向前端推送状态、阶段结果和错误。

### FR-AGENT-003 暂停与继续（P0）

在蓝图确认、质量争议或高风险内容处暂停，教师处理后继续。

### FR-AGENT-004 重试（P0）

单节点失败可重试，不能重复覆盖已确认结果。

### FR-AGENT-005 取消（P1）

允许取消未完成任务，并保留已完成节点结果。

### FR-AGENT-006 运行日志（P1）

- **单文件导出**：面板顶部提供一键导出该模块特定格式文件（如 `.docx`、`.pptx`、`.md`）功能。

# 10. 非功能需求

## 10.1 性能

MVP 建议目标：

- 普通 API P95 小于 800ms，不含 LLM；
- 课程蓝图生成一般不超过 90 秒；
- 完整课程包一般在 3—8 分钟内完成，取决于模型；
- 前端应持续显示进度，不出现长时间空白；
- 文件导出失败可单独重试。

## 10.2 可靠性

- Agent 节点幂等；
- 状态持久化；
- 进程重启后任务可恢复或明确标记失败；
- 自动重试采用上限和退避；
- 不因一个资源失败丢失其他已完成资源。

## 10.3 安全

- 密码哈希；
- JWT 或安全会话；
- 资源级权限校验；
- 上传文件扩展名和 MIME 检查；
- 文件名清理和目录穿越防护；
- API Key 不进入日志；
- 个人信息检测；
- 数据删除和备份策略；
- 审计关键操作。

## 10.4 可维护性

- Agent Prompt 版本化；
- Pydantic Schema 作为接口契约；
- 业务逻辑与模型调用分离；
- 文档渲染与内容生成分离；
- 配置通过环境变量和配置文件管理；
- 单元测试覆盖规则和数据转换。

## 10.5 可扩展性

- SQLite 可迁移到 PostgreSQL；
- 本地文件可迁移到 S3/MinIO；
- 进程内任务可迁移到 Redis Worker；
- 模型通过统一适配器接入；
- 向量检索通过接口抽象，MVP 可不用独立向量库。

## 10.6 可用性

- 自动保存；
- 清晰错误信息；
- 支持继续生成；
- 支持示例课程；
- 重要操作有确认；
- 复杂字段提供解释和示例；
- 不向教师暴露不必要的 Agent 技术术语。

## 10.7 可访问性

P1 建议：

- 键盘可操作；
- 颜色不作为唯一状态提示；
- 导出文档使用标题层级；
- 图片提供替代文本占位；
- 字体、字号和对比度满足基本可读性。

# 13. 需求决策原则

当功能、时间和成本冲突时，优先级如下：

1. 教学准确性与安全；
2. 多资源一致性；
3. 教师可编辑和可恢复；
4. 可导出、可实际使用；
5. 生成速度；
6. 视觉效果；
7. 自动化程度。

这意味着 MVP 宁可少做自动视频和复杂动画，也要先把课程蓝图、资源一致性、质量检查和可编辑导出做好。
